# @deepseek-ai/dsh-project-memory-local

[English](README.md) | 中文

本包是 `@deepseek-ai/dsh-project-foundations` 的本地项目记忆 Service Provider。它通过已配置的 `ctx.fs` 提供方在一个有字节上限的 JSON 文档中存储已提炼的 `ProjectMemoryRecord` 条目。

## 行为

- `put()` 按调用方拥有的标识符原子插入或替换记录。它保留分离副本，绝不存储模型 transcript、外部适配器响应、凭据或实现写入指令。
- `search()` 会在记录的标识符、种类、概述和证据中匹配每个不区分大小写的查询词。它按最新时间戳、再按标识符返回分离的匹配项；决策记录走同一检索路径。
- 文档不存在时读取为空。无效 UTF-8、格式错误的 JSON、重复标识符、不受支持的记录种类和超出上限的输入都会快速失败，而不会被忽略。
- 提供方只通过 `ctx.fs` 读写，其中包括配置的字节上限和受保护的原子发布。它不访问宿主文件系统 API，也不改变项目 worktree。

## 配置

| 键 | 含义 |
| --- | --- |
| `path` | 由所选文件系统提供方解析的项目记忆 JSON 文档。 |
| `maxBytes` | 完整 JSON 文档的包含式字节上限。 |

## 模型体验

### 项目记忆

#### 模型看到的内容

没有直接内容。经过批准门控的规划消费方决定哪些返回的提炼记录进入已记录的上下文包。

#### Token 影响

在消费方将选定记录序列化为模型可见上下文之前，token 消耗为零。

#### KV Cache 影响

此 Service Provider 不产生影响。消费方会在可复用请求前缀之后添加选定记录。

## 已知限制与延期工作

- 文档使用乐观的受保护替换。并发写入方会收到文件系统提供方的陈旧写入错误，而不会静默合并记录。
- 本包只提供 Service Provider 角色。Phase 1 规划消费方负责检索策略、批准门控、会话记录、外部提升以及所有实现写入。
